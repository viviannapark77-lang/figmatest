# /build-page

**이 작업을 인라인으로 하지 않는다.** 반드시 `Agent`(subagent_type: `component-builder`)를 호출한다.

이 스킬은 **새 컴포넌트를 만들지 않는다.** 이미 있는 컴포넌트를 조립해 화면 하나를 만드는
작업이다. 조립에 필요한 컴포넌트가 없으면 이 스킬을 쓰지 않고 `/figma-to-code` 또는
`/new-component`로 그 컴포넌트를 먼저 만든다.

## 절차

### 1. 입력 확인 (호출 전)

| 필요 | 없으면 |
|---|---|
| 대상 페이지의 PRD (`docs/prd-list` 등) | 없으면 `/analyze-prd` 또는 사용자에게 먼저 확인한다 |
| 페이지의 정확한 레이아웃 근거 — Figma 링크/노드, 또는 이미 검증된 과거 구현(git 히스토리 등) | 근거 없이 배치를 추측하지 않는다. Figma 노드가 있다면 **메인 세션 또는 `figma-implementer`가 먼저 읽어** 어떤 기존 컴포넌트가 어떤 노드에 대응하는지, 레이아웃 프레임의 패딩·간격 값이 무엇인지 확정해 넘긴다 — `component-builder`는 Figma MCP를 쓰지 않는다 |
| 페이지 이름·경로 (`src/pages/<Name>/`) | 사용자에게 묻는다 |
| 라우트 추가 여부 (`src/main.tsx`에 `<Route>` 한 줄) | 사용자에게 확인 — 기존 라우트(`/` 리다이렉트 대상 등)는 요청 없이 바꾸지 않는다 |

### 2. 에이전트 호출

`Agent`를 `subagent_type: "component-builder"`로 호출한다. 프롬프트에 반드시 포함:

- 확정된 레이아웃 근거 (노드별 컴포넌트 매핑, 패딩·간격 값, 넘길 props) — **추측하지 말고
  이미 확정된 값만 쓰라**고 명시
- PRD 내용 (타겟 사용자·기능·성공 기준) — 버튼 활성화 조건, 에러 처리 등 동작 로직의 근거
- 페이지 이름·경로
- `src/main.tsx`에 추가할 라우트 한 줄 (다른 기존 라우트는 건드리지 말라고 명시)
- "요청받지 않은 페이지·컴포넌트·라우트를 함께 만들지 말라"

### 3. 반환 검증

- 산출물: `<Page>.tsx` · `<Page>.stories.tsx` · `<Page>.design.md` (Figma URL + 토큰 매핑 + 이 페이지가 조립한 기존 컴포넌트 목록)
- **요청 대비 추가한 것 없음** 확인 — 요청받지 않은 다른 페이지·라우트가 함께 생기지 않았다
- raw 값 0건 (레이어 3 hook이 이미 파일 쓰기 시점에 차단했을 것이다)

### 4. 검증 게이트

`/review-design`을 실행한다. **FAIL이면 완료를 선언하지 않는다.**
