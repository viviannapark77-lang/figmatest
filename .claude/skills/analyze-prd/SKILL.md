# /analyze-prd

**이 작업을 인라인으로 하지 않는다.** 반드시 `Agent`(subagent_type: `prd-analyzer`)를 호출한다.

## 절차

### 1. 입력 확인 (호출 전)

| 필요 | 없으면 |
|---|---|
| PRD 원문 또는 파일 경로 | 사용자에게 묻는다. 추측하지 않는다 |
| 대상 화면/기능명 (`{FeatureName}` — 산출물 파일명에 쓴다) | 사용자에게 묻는다 |

### 2. 에이전트 호출

`Agent`를 `subagent_type: "prd-analyzer"`로 호출한다. 프롬프트에 반드시 포함:

- PRD 원문, 또는 읽어야 할 파일 경로
- 화면/기능명
- "레이아웃·배치·Figma 노드 조작은 다루지 말고, 컴포넌트 목록만 구조화해 반환하라"

### 3. 반환 검증 + 파일 저장

`prd-analyzer`는 `Write` 권한이 없어 파일을 직접 쓰지 않는다. 반환된 Markdown이 아래를
전부 포함하는지 확인한 뒤, **메인 세션이** `/docs/ui_specs/{FeatureName}-UI_Components.md`로 저장한다.

- 화면 목적 1줄 요약
- 영역별(Header/Sidebar/Main/Modal) 컴포넌트 리스트
- 컴포넌트별 `[유형·레이블·필수여부·상태]`

다음이면 다시 요청한다:
- 위 항목 중 빠진 것이 있다
- 설명이 30단어를 넘는 장황한 서술이다
- PRD에 없는 기능·장식이 임의로 추가돼 있다
- 레이아웃/배치 판단(무엇이 위·아래에 오는지 등)이 섞여 있다

### 4. 다음 단계

이 산출물은 후속 레이아웃/Figma 생성 작업(Layout Architect류)의 입력이다. 이 스킬은
레이아웃 설계나 Figma 노드 조작을 하지 않는다 — 그 작업은 별도 스킬/에이전트의 역할이다.
