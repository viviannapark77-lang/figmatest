# /checkpoint

**에이전트를 호출하지 않는다.** 메인 세션이 직접 실행한다 — 디자인/토큰 작업이 아니라 저장소 기록 작업이다.

기록은 **커밋 메시지 하나**로 남긴다. 별도 진행 로그 파일은 만들지 않는다.

## 절차

### 1. 현재 상태 파악

병렬로 실행한다.

- `git status` (untracked 포함, `-uall` 금지)
- `git diff` (unstaged) + `git diff --staged`
- `git log --oneline -10` — 이 저장소 커밋 메시지 스타일 확인 (`feat:`/`fix:`/`chore:`/`refactor:` 접두사 + 한글 설명)

### 2. 변경 없음이면 중단

untracked까지 포함해 변경사항이 전혀 없으면 커밋하지 않는다. "기록할 변경사항 없음"만 보고하고 끝낸다. 빈 커밋을 만들지 않는다.

### 3. 위험 파일 점검

`git status` 결과에 `.env`, `*.pem`, `credentials*`, `*.key` 등 비밀값처럼 보이는 파일이 있으면, 스테이징 전에 그 파일 내용을 확인한다. 실제 비밀값이 들어 있으면 그 파일은 스테이징에서 제외하고 이유를 보고한다.

### 4. 스테이징 + 커밋

- 확인된 파일만 이름으로 `git add`한다. `git add -A`/`git add .`로 무분별하게 올리지 않는다.
- 스테이징 후 `git status`로 무엇이 포함됐는지 다시 확인한다.
- 커밋 메시지는 이 저장소의 기존 스타일을 따른다 — 무엇을 왜 바꿨는지 1~2문장, 타입 접두사 포함.
- HEREDOC으로 커밋해 줄바꿈·따옴표 문제를 피한다.

```
git commit -m "$(cat <<'EOF'
<type>: <한글 요약>

Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>
EOF
)"
```

### 5. push

- 현재 브랜치의 원격 추적 브랜치로 push한다.
- 추적 브랜치가 없으면 `git push -u origin <현재 브랜치>`로 최초 push한다.
- `--force`, `--no-verify` 등은 쓰지 않는다.
- push가 거부되면(원격이 앞서 있는 등) 강제로 덮어쓰지 않는다. 실패 원인을 그대로 보고하고, `pull --rebase` 등 해결 방법은 사용자에게 먼저 확인한다.

### 6. 결과 보고

커밋 해시, 커밋 메시지 요약, push된 브랜치를 보고한다. 실패한 단계가 있으면 어디서 왜 실패했는지 함께 보고한다.

## 하지 않는 것

- 빈 커밋
- 확인 없는 전체 스테이징(`-A`/`.`)
- force push, 훅 스킵(`--no-verify`)
- 별도 진행 로그 파일 생성 (기록은 커밋 메시지로 충분하다)
